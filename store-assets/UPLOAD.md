# RelayIQ upload package

Package: com.k.hosken.relayiq
Version: 1.0 (version code 2)
Minimum Android: 8.0 (API 26). Target API: 37.

## Files to use

- `RelayIQ-1.0-v2.aab`: signed bundle for the Play Console release upload.
- `store-assets/`: icon, feature graphic, screenshots, listing copy and release notes.
- `mapping.txt`: keep with this exact release for crash deobfuscation. The bundle
  also contains the R8 mapping metadata when generated by the Android build.
- `privacy-policy.html`: corrected privacy policy ready to host.
- `SHA256SUMS.txt`: checksums for this package.

The root `play-upload` folder is generated locally and ignored by Git. Do not
upload the keystore, signing passwords, source project, or the whole folder to
Play Console. Upload the `.aab` in the release screen and images in the listing.

## Console steps

1. Open the Kayl Down Under developer account. Open the existing RelayIQ app if
   present; otherwise create RelayIQ as a free app in English, Communication.
2. Start an internal testing release and upload `RelayIQ-1.0-v2.aab`. Use Play
   App Signing when prompted. If version code 2 was already used, increment
   `versionCode` in `app/build.gradle.kts`, rebuild, and package that new bundle.
3. Paste the release notes. Fill the listing from `store-assets/play-listing.md`
   and upload the icon, feature graphic, and phone screenshots.
4. Publish the updated root `index.html` to the existing GitHub Pages site and
   verify https://kayldownunder.github.io/RelayIQ/ shows September 20, 2026.
   The previously live page was reachable but still showed September 3.
5. App content forms are complete as of September 23, 2026 (all 10 declarations
   actioned): privacy policy, sign-in details, ads, content rating, target
   audience, data safety, government apps, financial features, health apps.
   Data safety was declared as: collects Messages / Other in-app messages,
   optional, app functionality, not ephemeral, encrypted in transit, no
   sharing, no accounts. The provider API key was not declared as a separate
   data type - it is the user's own credential sent only to that provider, and
   no Play data type covers it. Revisit if Google's guidance changes.
6. Store settings are set: category Communication, contact email
   kayl.hosken@gmail.com, website https://kayldownunder.github.io/RelayIQ/.
7. The default store listing text (app name, short and full description) is
   saved as a draft. The icon, feature graphic and phone screenshots still need
   uploading by hand - the Console's "Add assets" control opens the operating
   system file picker, which cannot be driven from this session. Files are in
   `store-assets/`. The listing cannot be fully saved until they are added.
8. Add internal testers and review the pre-launch report. Test dictation,
   polishing with each provider, and sharing on real devices. For production,
   complete any closed-testing and account-verification requirements shown in
   your Console dashboard.

## Reviewer instructions

No RelayIQ account or login is required. Type a message or tap Speak to use the
device's speech recognizer. Tap a messaging icon to open another app with the
message filled in; choose a recipient and send from that app. Settings controls
font, size and colour. To test optional AI polishing, open Settings, tap the
API Key lock, choose a provider and enter a valid API key for that provider.
The app does not supply keys or include an AI subscription. Without a key it
shows a prompt; typing, dictation and sharing remain available. If Play requires
reviewer access to paid provider functionality, arrange dedicated restricted
review credentials in Play Console, never in source control or screenshots.

## Verification limits

The local unit-test suite is the starter arithmetic test, not functional
coverage. Provider requests need separately supplied credentials and have not
been validated end to end for this release. A successful build and upload do
not constitute Google Play approval. The hosted policy update and Console
forms remain publication steps.

Official upload guide: https://support.google.com/googleplay/android-developer/answer/9859348
